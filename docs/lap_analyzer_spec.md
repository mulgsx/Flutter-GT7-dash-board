# GT7 Lap Analyzer — 実装仕様書

## 背景・目的

「全国都道府県対抗eスポーツ選手権 グランツーリスモ7部門」（通称：国体予選）に向けた
**練習支援・ラップ分析アプリ**を新規開発する。既存の `Flutter-GT7-dash-board`
リポジトリをベースとし、UDP受信・Salsa20復号ロジックを流用しつつ、新しいアプリとして
機能を追加する（既存のダッシュボード画面自体は変更しない）。

対象ユーザーは開発者本人。速い人のラップ（ターゲット）と自分のベストラップを読み込み、
オフライン比較・リアルタイム比較を行うことで練習の質を上げることが目的。

## アプリ全体像

起動直後のホーム画面には、以下3つのボタンのみを配置する（シンプルな導線）：

1. **ターゲット読み込み**
2. **自分のベストラップ読み込み**
3. **リアルタイム差分比較**

現在ターゲット・ベストが読み込み済みかどうか、読み込み済みならそのラップタイムを
ホーム画面に小さく表示しておく（例: `ターゲット: 1'09.266` / `ベスト: 1'10.320`）。

### 1. ターゲット読み込み

- タップすると計測待機状態になり、「1周走ってください」等を表示
- 次のラップ境界（`current_lap`の増加）からラップ境界までを1周分のデータとして
  丸ごとキャプチャする（ボタンを押した瞬間が周回の途中でも、次の周回開始を
  待ってから記録を始める＝必ず1周まるごとのデータになるようにする）
- 1周分のデータが正常に取得できたことを確認したら、**自動的に保存**する
  （保存確認ダイアログ等は不要）
- 既にターゲットが読み込み済みの場合は、**既存データを削除して新しいデータで
  上書き**する（常に最新の1件のみを保持）
- 保存後は自動的にホーム画面へ戻り、ターゲットタイムを表示する

### 2. 自分のベストラップ読み込み

- 上記と全く同じ流れ（計測→1周分キャプチャ→自動保存→既存があれば上書き）
- 保存先が「ベスト」枠になる点のみ異なる

ターゲットとベストの両方が読み込まれている状態になったら、**オフラインでの
比較分析画面**（両者の入力ライン・セクター差分を並べて見る画面）を開けるように
しておく（ホーム画面から遷移できる導線を追加してよい）。

### 3. リアルタイム差分比較

- ターゲットが未読み込みの場合は「先にターゲットを読み込んでください」と案内し
  遷移させない
- 現在走行中のリアルタイムテレメトリと、読み込み済みのターゲットラップを
  **距離（走行距離）を基準に**突き合わせて、常時差分を表示する
- 表示内容（実装時の裁量に委ねる。以下は方向性の例）：
  - 現在の累積タイム差（ターゲットに対して何秒速い/遅いか）をリアルタイム更新
  - ブレーキング開始タイミングの差（ターゲットがブレーキを踏み始めた距離点と、
    自分が踏み始めた距離点の差を「◯m早い/遅い」のように表示）
  - スロットル/ブレーキの現在値とターゲットの同地点での値を並べて表示
- 詳細なUIレイアウト・グラフ形式は実装時に判断してよいが、「距離ベースで
  ターゲットと自分を突き合わせる」というロジックの骨格は上記の通りとする

## リポジトリ構成方針

既存リポジトリ（`Flutter-GT7-dash-board`）に以下を**新規追加**する形で進める。
既存の `lib/services/gt7_telemetry_service.dart`（UDP受信・Salsa20復号・パケット
パース）の既存の挙動・APIは変更せず、そのまま参照・再利用する。既存ダッシュボード
画面の構成・配置は一切変更しない。

```
lib/
  services/
    gt7_telemetry_service.dart      # 既存・流用（既存ロジックは変更なし）
  features/
    lap_analyzer/                   # 新規機能ディレクトリ
      models/
        telemetry_sample.dart       # 1サンプル分の時系列データ点
        lap_capture.dart            # 1周分のラップ（種別・開始時刻・開始速度・サンプル列）
      services/
        lap_capture_service.dart    # 周回境界の検知・1周分のキャプチャ制御
        reference_lap_store.dart    # ターゲット/ベストの永続保存（上書き方式）
        lap_log_writer.dart         # 毎周・自動でtxtログを書き出す
        realtime_diff_service.dart  # 距離ベースでの現在値とターゲットの突き合わせ
      screens/
        home_screen.dart            # 3ボタンのホーム画面
        capture_screen.dart         # ターゲット/ベスト読み込み共通画面（モード切替）
        offline_compare_screen.dart # ターゲット vs ベストのオフライン比較
        realtime_compare_screen.dart # リアルタイム差分比較
      widgets/
        input_trace_chart.dart      # throttle/brakeの距離軸チャート（オフライン比較用）
        live_delta_indicator.dart   # リアルタイムの時間差・ブレーキ地点差の表示
```

## 使用パッケージ（新規追加分）

- `path_provider`：アプリのドキュメントディレクトリ（保存先）を取得
- `fl_chart`：オフライン比較画面のグラフ描画
- （既存流用）Salsa20復号ロジック一式

## データモデル

### TelemetrySample
```dart
class TelemetrySample {
  final int elapsedMs;         // ラップ開始からの経過時間
  final double distanceM;      // ラップ開始からの走行距離（積算）
  final double speedKmh;
  final double throttle;       // 0.0〜1.0
  final double brake;          // 0.0〜1.0
  final double? steering;      // ※GT7 UDPに生のステアリング角フィールドは確認できず
                                //   常にnull。表示側はthrottle/brakeのみにフォールバック。
  final double posX, posY, posZ;
}
```

### LapCapture
```dart
enum LapType { target, best, practice }

class LapCapture {
  final LapType type;
  final DateTime startTime;
  final double startSpeedKmh;   // ラップ開始（周回境界通過）時点の速度
  final int lapTimeMs;
  final List<TelemetrySample> samples;
}
```

## 永続化方針（DBは使わず、ファイルベースでシンプルに）

sqliteは使わず、アプリのドキュメントディレクトリ配下にシンプルなファイル構成で
永続化する。

```
<Documents>/gt7_lap_analyzer/
  reference/
    target_lap.json     # 現在のターゲット（読み込むたびに上書き）
    best_lap.json        # 現在の自分のベスト（読み込むたびに上書き）
  logs/
    2026-08-22_23-05-12_PRACTICE.txt
    2026-08-22_23-06-40_TARGET.txt
    2026-08-22_23-07-55_BEST.txt
```

- `reference/target_lap.json` / `best_lap.json`：`LapCapture`をJSONシリアライズして
  保存。アプリ再起動後もここから読み込むことで前回のターゲット・ベストを復元する
  （`reference_lap_store.dart`が担当）
- `logs/`：**ボタン操作を介さず、ラップが1周完了するたびに自動で**txtファイルを
  書き出す（`lap_log_writer.dart`が担当）。対象は種別を問わず**全ラップ**
  （通常の練習走行中の全ラップ含む）

## ラップ検知・記録ロジック（共通基盤）

既存 `gt7_telemetry_service.dart` がデコードするパケットの`current_lap`の増加を
検知したタイミングで「1周完了」とみなし、その周回中にバッファしていた
`TelemetrySample`列から`LapCapture`を1件確定させる。この確定処理は常時動作しており、
以下の2つの用途に同時に使われる：

1. **常時ログ書き出し**：確定した`LapCapture`は、種別（後述のキャプチャモードに
   応じてTARGET/BEST、それ以外はPRACTICE）を付けてそのまま`lap_log_writer`に渡し、
   txtファイルとして書き出す（毎周・自動・ボタン不要）
2. **ターゲット/ベストの保存**：「ターゲット読み込み」または「ベスト読み込み」
   モードが有効なときに確定した次の1周だけ、`reference_lap_store`に渡して
   該当スロットを上書き保存し、モードを自動的に解除してホーム画面に戻る

サンプリングは受信パケットごと（60Hz想定）でバッファに積んでよい。txt出力・比較用
には後述のとおり間引いてよい。

## TXTログのフォーマット

ヘッダー3行＋データ本体（間引いた時系列、CSV形式）とする。サンプリング間隔は
実装時の裁量で構わないが、目安として **200ms間隔（5Hz）** 程度に間引いて出力する
（60Hzそのままだと1周で数千行になり読みづらいため）。

```
TYPE: TARGET
START_TIME: 2026-08-22T23:06:40+09:00
START_SPEED_KMH: 42.3
LAP_TIME_MS: 69266
elapsed_ms,distance_m,speed_kmh,throttle,brake,steering,pos_x,pos_y,pos_z
0,0.0,42.3,0.80,0.00,,123.4,0.0,-56.7
200,11.7,58.1,1.00,0.00,,131.2,0.0,-49.3
...
```

- `TYPE`は`TARGET` / `BEST` / `PRACTICE`のいずれか
- `steering`列は値が取得できない場合空欄のままでよい（無理に推定しない）
- ファイル名は `YYYY-MM-DD_HH-mm-ss_<TYPE>.txt`（ラップ開始時刻ベース）とし、
  `logs/`フォルダにボタン操作なしで自動生成される

## リアルタイム差分比較の実装方針

- `realtime_diff_service.dart`が、ロード済みターゲットの`List<TelemetrySample>`を
  距離順に保持し、現在の走行距離に対して**最も近い距離のターゲットサンプル**を
  都度検索する（距離配列は単調増加なので二分探索でよい）

### 表示項目（明示リスト）

以下を表示対象とする。①②は必須、③〜⑥は実装時の優先度・UIレイアウトの裁量に
委ねてよいが、**ロジック自体は実装しておく**（表示のON/OFFや配置は自由）。

1. **【必須】累積タイム差分（デルタタイム）の推移**
   - ターゲット側の該当距離点での`elapsedMs`と、自分の現在の`elapsedMs`との差分を
     走行距離に対して連続的にプロットする、いわゆる「デルタバー」表示
   - 数値（現在の差分秒数、色分け：速い=緑/遅い=赤）とグラフの両方を持たせる

2. **【必須】ブレーキング開始地点の差**
   - ターゲットのサンプル列から「brakeが初めて閾値（例: 0.1）を超えた距離点」を
     ターゲット読み込み時に一度だけ計算しておく
   - 自分が同様にブレーキを踏み始めた距離点との差（m）を、そのブレーキング区間に
     入ったタイミングで表示する

3. **アクセル踏み込み開始地点の差（コーナー立ち上がり）**
   - ブレーキ地点差と同じロジックで、「throttleが閾値（例: 0.1）を超えた距離点」の
     差を計算する。コーナー立ち上がりの加速タイミングの差が分かる

4. **コーナー進入速度の差**
   - ブレーキング終了地点（brakeが閾値を下回った瞬間）でのスピードを比較する。
     「同じコーナーにどれだけ速く進入できているか」の指標になる

5. **区間最高速度の差**
   - ストレート等で到達した最高速度（ローカル極大値、またはブレーキ開始直前の
     速度）をターゲット・自分それぞれで記録し、その差を表示する

6. **走行ラインのズレ（横方向オフセット）**
   - `posX/posZ`（コース平面座標）を使い、ターゲットの軌跡に対して自分が現在
     どれだけ横方向にズレているか（垂線距離、簡易的には最近傍点との距離でよい）
     を算出する。走行ライン図（自分とターゲットの軌跡を重ねた俯瞰図）として
     表示できるとなお良いが、数値表示のみでも可

表示形式（グラフか数値かバーか等）や画面上の配置の詳細は実装時の裁量に委ねる。

## 段階的な実装・検証の進め方

1. 既存UDP受信・復号ロジックの動作確認（変更せず疎通のみ確認）
2. `TelemetrySample` / `LapCapture`のモデルと、周回境界検知によるラップ確定ロジック
   （`lap_capture_service.dart`）を実装し、ダミーパケットで単体テスト
3. `lap_log_writer.dart`を実装し、確定した`LapCapture`から正しいヘッダー・
   CSV本体のtxtが`logs/`に自動生成されることを確認
4. `reference_lap_store.dart`を実装し、target/best読み込み時の保存・上書き・
   アプリ再起動後の復元をテスト
5. `home_screen` → `capture_screen`（ターゲット/ベスト共通、モード引数で分岐）を実装
6. `offline_compare_screen`（ターゲット・ベストのthrottle/brake距離軸比較）を実装
7. `realtime_diff_service` → `realtime_compare_screen`を実装。まず時間差分の
   リアルタイム表示のみで動作確認し、その後ブレーキ地点差など追加表示を実装
8. `steering`フィールドの有無を実パケットのダンプで確認し、取れない場合は
   throttle/brakeのみの比較にフォールバック（無理にステアリング角を推定しない）

## 確認事項

- `flutter analyze` / `flutter test` を通すこと
- 既存のダッシュボード画面（メイン画面）の構成・配置・ロジックには一切手を入れないこと
- txtログの自動出力はボタン操作を介さず、ラップ完了のたびに常時動作すること
  （練習走行中の全ラップが対象。TARGET/BEST読み込み中のラップも含む）
- ステアリング角フィールドが確認できない場合、無理に他フィールドから推定せず
  「未対応」として明示すること（誤ったグラフ・差分を表示しない）

## 実装メモ（既存コードとの接続）

- ステアリング角フィールドはGT7 Packet Aのドキュメント（`docs/packet_structure.md`）
  上に存在しないことを確認済み。`TelemetrySample.steering`は常に`null`となる。
- `GT7Packet`（`lib/models/gt7_models.dart`）に、この機能のために
  `currentFuel` / `fuelCapacity` / `tyreTempFL〜RR` / `currentLap` / `totalLaps` /
  `bestLapMs` / `tcsActive` を追加済み（既存フィールド・既存ロジックには手を
  入れていない、純粋な追加）。
- `GT7TelemetryService`（既存）は個別のフィールドしか公開していないため、
  ラップ解析機能から生の`GT7Packet`を購読できるよう、既存の挙動・APIは一切
  変更せずに新しい通知（例：最新パケットの`ValueNotifier`）だけを追加している。
